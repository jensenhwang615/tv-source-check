# 央视 + 广东 + 中国香港 + 体育 直播源（自动检测）

一份只含 **CCTV 全系列 + 广东地区 + 中国香港 + 体育** 的直播清单，配一条自动流水线：
从公开上游采集候选 → 实测能不能播 → 只把能播的写进 `dist/valid.m3u` → 每 6 小时重跑一次。

> 只做直播，不含点播。只检测，不生产。

## 这个仓库有什么 / 没有什么

| 有 | 没有 |
|---|---|
| 采集脚本、检测脚本、GitHub Actions 工作流 | ❌ 任何点播聚合接口（苹果CMS `api.php/provide/vod` 之类） |
| 一份实测定时刷新的直播 m3u | ❌ 任何 spider JAR / JS（TVBox 那套远程加载的东西） |
| 每条线路的可用性报告 | ❌ 任何 VIP 解析接口 |
|  | ❌ 任何音视频文件（一帧都没有） |

## 三步上手

```bash
# 1. 建仓库推上去
git init && git add . && git commit -m "init" && git push

# 2. 仓库 Settings → Actions → General → Workflow permissions 选 "Read and write"

# 3. Actions 页面点 "源检测" → Run workflow
```

订阅地址（TVBox / 影视壳 / TiviMate / PotPlayer 都认）：

```
https://raw.githubusercontent.com/<你的用户名>/<仓库名>/main/dist/valid.m3u
```

本地手动跑：

```bash
pip install -r requirements.txt
python scripts/collect.py                                                    # 采候选
python scripts/check.py --playlist sources/streams.m3u sources/backup.m3u --out dist
```

## 文件结构

```
sources/streams.m3u    主清单（央视 + 广东），实测通过、比较稳的那些。可以手工增删
sources/backup.m3u     备用清单，来自某公开转播节点，含 CCTV-4/5、广东卫视等关键缺口
sources/hk.m3u         中国香港清单，实测通过。文件头写了每条的性质，先读再决定用不用
sources/sports.m3u     体育清单，实测通过。头部注释写了「哪些能拿、哪些拿不到、为什么」
sources/auto.m3u       自动生成（collect.py 产物），别手改
sources/collect.json   采集配置：上游地址 + 只要哪些分组。改这里就能改采集范围
scripts/collect.py     采集：拉上游 → 按关键词分到「央视 / 广东 / 香港 / 体育」→ 去重
scripts/check.py       检测：连通 → 内容 → HLS 主列表 → 拉第一个分片 → 判定
dist/valid.m3u         ← 订阅这个
dist/dead.m3u          失效的，用来看"整站挂了"还是"个别台挂了"
dist/report.md         人看的报告
```

## 检测到底测什么

不是「HTTP 200 就算活」——这类源最常见的坑就是返回 200 但给你一个"已失效"网页。

| 层级 | 检查 |
|---|---|
| 连通 | DNS、TCP、TLS、状态码，超时 8s |
| 内容 | 响应体是不是真的 `#EXTM3U`，还是伪装成流的 HTML |
| 主列表 | 解析 `#EXT-X-STREAM-INF`，按 BANDWIDTH 挑最高码率，读 `RESOLUTION` |
| **分片** | 往下钻一层，真去拉第一个 `.ts`/`.m4s`，拉不到就是假的 |
| 裸流 | 直接从连接读 64KB，能读到字节才算通 |

五档判定：

| 状态 | 含义 | 去处 |
|---|---|---|
| `OK` | 真的能播 | `valid.m3u` |
| `SUSPECT` | 能连但不正常（返回网页、分片拉不下来） | `dead.m3u` |
| `DEAD` | 连不上 / 4xx / 空响应 | `dead.m3u` |
| `BLOCKED` | **本机 IP 被该站限流**，不是源坏了 | `valid.m3u`（不算失效，不计入可用率） |
| `SKIP` | 组播地址（`rtp://`），云端测不了，不谎报 | 不写 |

`BLOCKED` 这一档是被现实逼出来的：主干 CDN 会按 IP 限流，GitHub 机房 IP 尤其容易中。
用 `--blocked-host 74.91.26.218` 指定，从它上面失败的条目就不会被误判成死源、也不会被踢出订阅清单。

## 香港这一块，先把话说清楚

104 条候选，通过 8 条。但「能播」和「该不该当主源」是两件事，性质得分开看：

| 频道 | 通过的线路从哪来 | 性质 |
|---|---|---|
| 凤凰卫视中文 / 资讯 / 香港台 | `fengshows.cn`（凤凰官方域名）的 CDN | **官方源**，最可靠，三条全通 |
| 翡翠台 ×3 线路 | 两个第三方转播节点（其中一条 relay 的是 TVB 付费 OTT「myTV SUPER」） | 未授权 |
| 明珠台 ×2（1 条已死） | 同上 | 未授权 |
| TVB Plus | 同上 | 未授权 |

**官方渠道实测全部拿不到，这是硬事实——不是我没找到：**

| 官方源 | 结果 |
|---|---|
| HOY TV `hoytv-live-stream.hoy.tv` | 超时（内地不通） |
| 港台 RTHK `rthktv3x-live.akamaized.net` | **HTTP 403，地域封锁** |
| 翡翠台内地合法直播渠道 | **不存在** |

所以「翡翠台怎么稳定看」这个问题，技术上是无解的。合法路径只有两条：

- **myTV SUPER**——TVB 官方 OTT，要香港 IP + 订阅
- **埋堆堆**——TVB 官方内地 App，有剧集点播，**没有翡翠台直播**

我的建议：翡翠台当「能用就用」，别当主粮。它的节点寿命以天计，TVB 的维权力度也远强于央视。
未收录 `华丽翡翠台`（Golden Jade）——实测它其实通，但那是 TVB 的付费频道，性质与免费台不同。

## 体育这一块：能拿到的和拿不到的

343 条候选，实测通过 78 条，但把「地域封锁的小台」滤掉之后，真正值得放进清单的只有 11 条。

**能拿到的：**

| 频道 | 性质 | 说明 |
|---|---|---|
| **五星体育** | 上海 SMG，国内免费台 | 走百视通 CDN `bp-livetytv.bestv.cn`，2 秒分片、延迟 ~150ms，本次唯一稳定出流的国内体育台 |
| beIN SPORTS XTRA | **beIN 官方免费 FAST** | 足球赛事与集锦，1080p |
| FIFA+ / NBC Sports NOW / DD Sports / Sportitalia / TyC Sports | **各台官方免费** | 都是官方 FAST 频道，合法、长期可用，但内容以演播室、集锦、冷门场次为主 |
| ESPN 拉美 1~4 | **第三方转播**（拉美区 ESPN 持西甲、欧冠版权） | 足球内容最对口，但节点寿命以天计，别当主粮 |

**拿不到的（不是没找，是硬事实）：**

| 想要的 | 结论 |
|---|---|
| 劲爆体育 | SiTV 付费频道。4 条候选全 403/失效，**无公开流** |
| 英国 Sky Sports、TNT Sports（欧冠英国持权方） | 在所有公开清单里**已被移除**（版权方维权） |
| 美国 ESPN 主频、beIN Sports 1~8、DAZN、Eleven、Premier Sports | 实测**全部 HTTP 403**——内地 IP 被地域封锁，几毫秒就拒，不是源坏了 |
| 日本 J SPORTS 1~4、WOWOW | Free-TV 清单里直接写 **[NO PUBLIC STREAM]**，维护者明确说没有公开流（付费卫星台） |
| 韩国 SBS Sports / KBS N Sports / MBC Sports+ | 公开清单里**完全没有条目**（付费有线台） |

顺带说一个自己踩的坑：一开始这些源全被判 DEAD，因为**部分 CDN 校验 `Referer`**。
现在 `check.py` 遇到 401/403 会自动补上「源站 Referer」重试一次，这一步让通过数从 64 涨到 78。
`五星体育` 那条在 m3u 里也带了 `#EXTVLCOPT:http-referrer=`，VLC / TiviMate / 部分 TVBox 认这行。

## 足球（西甲、欧冠）怎么看不踩坑

先把结论摆出来：**这两项赛事在国内没有免费的全量直播，靠 m3u 源更不可能稳定**。
版权是独家授权，公开流必然是盗链，而盗链的寿命和画质都不够看 90 分钟。

| 想看 | 渠道 | 花钱 | 稳定性 |
|---|---|---|---|
| **西甲** | **CCTV-5 / CCTV-5+**（本仓库已含）——2026 年 4 月央视集齐五大联赛版权，每轮挑场次免费播 | 0 | ★★★★★ |
| 西甲（想看全） | 咪咕视频 / 爱奇艺体育（按赛季版权方不同） | 会员 | ★★★★★ |
| **欧冠** | **爱奇艺体育**——2026 年续约至 2031 年，中国大陆全媒体独家 | 会员 | ★★★★★ |
| 欧冠（免费） | 央视能不能播每赛季都在变，说法不一，**以当期节目单为准**；央视频有集锦 | 0 | 场次不确定 |
| 英超 | 咪咕视频（2025/26–2027/28 内地及澳门新媒体独家） | 会员 | ★★★★★ |
| 粤语解说 | **广东体育**（本仓库已含，免费）——英超、西甲场次会转 | 0 | ★★★★ |
| 国际免费正规源 | **UEFA.tv**（欧足联官方，免费看回放与部分赛事）、**FIFA+**（本仓库已含） | 0 | ★★★★★ |

一句话：**西甲挂 CCTV-5 节目单，欧冠只能买爱奇艺，其余靠广东体育捡场次。** 清单里的体育台是补充，不是替代。

## 三个必须知道的坑

**1. GitHub Actions 的机器不在国内。** runner 跑在 Azure 美国/欧洲机房，测大陆 CDN 会大量假失败,
延迟数字也没参考价值。**这个项目最该做的第一件事是把 runner 换成你自己的电脑**：
仓库 Settings → Actions → Runners → New self-hosted runner → 选 Windows 按提示装，
然后把 `.github/workflows/check.yml` 里 `runs-on: ubuntu-latest` 改成 `runs-on: self-hosted`。
家里那台常开的机器跑，结果才准。

**2. 转播节点会限流，而且限的是 IP。** 这是我自己踩到的：探测 `74.91.26.218` 时连发一百多个请求，
之后整个 IP 全部 404，连之前能播的台都不给了；等了十几分钟才恢复。
所以 `backup.m3u` 里那些地址**别用脚本批量刷**，正常看不会触发。
家用宽带 IP 一般是干净的新 IP，反而比机房 IP 更容易通过。

**3. 单一源"时好时坏"是常态。** 直播源经常这会儿通、下会儿 503。
每 6 小时跑一次，只在 `valid.m3u` 里留下当时能播的，本身就是在自动纠错。

## 零维护的兜底方案

m3u 这套东西本质上是「别人家的服务器」，再自动也有天花板。真正不会死的只有官方渠道：

| 想看 | 装什么 | 成本 |
|---|---|---|
| CCTV 全频道直播 + 7 天回看 | **央视频**（央视官方，免费，手机/电视都能装） | 0，永不死 |
| 广东卫视、珠江、广东体育 | **触电新闻**（广东广播电视台官方） | 0 |
| 佛山本地台 | **佛山+**（佛山传媒官方） | 0 |
| 广州台 | 广州台官方 App / `tencentplaybusiness.gztv.com` 直链 | 0 |
| TVB 剧集（非直播） | **埋堆堆**（TVB 官方内地 App） | 0，部分会员 |
| 凤凰卫视 | 凤凰秀 App（凤凰官方） | 0 |

建议：**央视频当主力，m3u 清单当"电视上懒得装 App 时"的备选。** 两条腿走路，哪条断了都不至于没得看。
